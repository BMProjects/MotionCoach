# 多人分析：目标稳定、需求与界面（设计，2026-10-21）

> 状态（2026-10-23）：已实施并在 4 段真实集体视频上运行。§10–§12 为密集人群、镜头补偿、统一时间轴（个人投票与人工修正）与集体工作台；最初实现（2026-10-21，§7、§8）为：多人姿态、身份、站位、练习者筛选、逐人比较、同步与一致性；网页“画面中的人数 → 多人”，集体总览、身份核对、逐人复用单人工作台；命令行 `motioncoach group`。
> 现状：单人流程里每个姿态算法每帧只输出一个人。
> - MediaPipe 设 `num_poses=1`；
> - RTM / YOLO 用 `perception/base.py::select_target`：取与上一帧框 IoU 最大者，IoU ≤ 0.1 时改取面积最大者。
> 这是最简单的“目标保持”，没有身份概念：两人交叉或短暂遮挡时会切到另一人。

## 1. 多人与单人的需求是否一致

**不完全一致。** 单人分析的核心是“这个人哪里与标准不同、怎么改”。多人分析包含两类需求：

| 需求 | 单人 | 多人（集体练习 / 课堂） |
|---|---|---|
| 逐人与标准比较、给出矫正 | 核心 | 仍需要，但通常只对教练选中的少数人展开 |
| 总览：谁需要关注 | — | **核心**：一屏看清每人每式的达标情况，按问题严重度排序 |
| 整齐度 / 同步 | — | **新增**：每人相对标准或集体的时间超前/滞后、动作幅度一致性 |
| 无标准视频时的参照 | 不适用 | 可用**集体共识**（同一时刻多数人的姿态中位数）或领操者作参照 |
| 队形 | — | 可选：间距、行列是否整齐（需要地面标定，见 `SCALE_DESIGN.md` 精确档） |
| 身份 | 隐含（只有一个人） | **前提**：每个人从头到尾必须是同一个 ID，否则逐人结论全部无效 |

结论：
- 逐人比较可以**原样复用单人引擎**：多人 = 多条单人姿态序列，每条走现有的区间定位、模板搜索与规则判定。
- 新增三部分：身份保持（§2）、集体层指标（§3）、总览界面（§5）。

## 2. 保证识别目标稳定（不跳人）

### 2.1 原因

身份跳变来自三种情况：
1. **交叉与遮挡**：前后排、相邻两人手臂重叠时检测框合并或丢失；
2. **外观相近**：集体练习常穿统一服装，基于外观的再识别（ReID）区分力弱；
3. **逐帧独立选择**：现有 `select_target` 只看上一帧，一旦丢失就取“最大的人”。

### 2.2 方案：离线两遍跟踪（分析是离线的，可以看完整段视频再定身份）

**第一遍：在线关联生成短轨迹（tracklet），宁断勿错**
- 检测 + 关联用成熟的多目标跟踪器：
  - ByteTrack：低分检测框也参与第二轮关联，遮挡时不易断；
  - OC-SORT：以观测为中心修正运动模型，适合非线性运动与遮挡；
  - BoT-SORT：相机运动补偿 + ReID。
- **关联代价加入姿态信息**，不只用框 IoU：
  - 关键点相似度 OKS；
  - 骨长一致性（同一个人的上臂、大腿长度稳定，见 `engine/normalize.bone_lengths`）；
  - 髋中点位置。
  八段锦基本原地练习，位置先验很强。
- 阈值偏严：代价不确定时**断开**轨迹而不是硬接。断开以后可以修复，接错则会把两个人的动作混在一起，错误不可见。

**第二遍：全局拼接**
- 把短轨迹当作节点，按以下线索求全局最优连接（匈牙利算法或最小费用流）：
  - 时间间隔；
  - 断点两侧的位置与速度连续性；
  - 骨长签名；
  - 外观：衣服颜色直方图、ReID 向量。
- **站位锚定**：集体练习时，先用开头数秒的稳定站位给每人分配“位置槽”，后续轨迹优先归入最近的槽。
- **交叉校验**：在两条轨迹靠近又分开的地方比较“交换前后”的骨长签名与运动连续性，代价更低的一方胜出。

**第三遍：人工确认（只在需要时）**
- 系统给出每条身份轨迹的置信度、断点与疑似交换点。
- 教练可以合并、拆分、改名或排除（如路人），确认结果随报告保存。

### 2.3 算法选型

| 方案 | 每帧代价 | 身份支持 | 备注 |
|---|---|---|---|
| 检测器 + 逐人 RTMPose/RTMW（自上而下） | 随人数线性增长 | 需外接跟踪器 | 单人精度最好的路线；rtmlib 自带 `PoseTracker`，只是贪心 IoU 跟踪，不够 |
| RTMO（单阶段多人） | 与人数基本无关 | 需外接跟踪器 | 人多时最省；横评中头部有效率只有 66–68%，第四式转头受影响 |
| YOLO-pose + 内置跟踪（ByteTrack / BoT-SORT / OC-SORT） | 低 | 内置 | 工程最快；AGPL-3.0，商用需授权 |
| MediaPipe `num_poses > 1` | 随人数增长 | **无 ID**（结果只有关键点与掩码） | 只适合手机端少量人数 |

建议：
- 服务器：检测 + 跟踪 + 逐人姿态，跟踪器选 ByteTrack 或 OC-SORT 的原始实现（需逐个核对许可证），再加上 §2.2 的姿态代价与全局拼接；
- 人数多（> 8）时改用 RTMO。

### 2.4 验证（上线前必须测）

- **指标**：
  - ID 切换次数；
  - IDF1：正确识别的检测比例，Ristani et al. 2016；
  - HOTA：同时衡量检测与关联，Luiten et al. 2020；
  - 下游：每人的重复 F1 与定势命中（沿用 `research/metrics.py`）。
- **数据**：
  1. 合成：把现有单人视频左右拼接，得到身份已知的 2–3 人视频，零成本；无法模拟交叉。
  2. 实拍：3–6 人集体练习，含前后排遮挡与一次换位，人工逐秒标注身份。
- **验收建议**：每 10 分钟 ID 切换 ≤ 1 次；每次切换都要能在界面上被标出，不能静默发生。

## 3. 多人分析的功能参数

| 参数 | 取值 / 默认 | 说明 |
|---|---|---|
| `max_persons` | 默认 6 | 决定计算量；超出时按画面占比取前 N 位 |
| `min_person_height` | 画高的 25%，或 ≥ 400 px | 低于此尺寸的人只计入总览，不做逐项判定（单人数据中 320×568 已出现足部不可测） |
| `target` | 全部 / 指定 ID / 领操者 | 指定 ID 时只对这些人做完整分析 |
| `reference` | 标准视频 / 领操者 / 集体共识 | 后两者用于无标准视频的课堂 |
| `id_confirm` | 自动 / 需人工确认 | 低置信时强制确认后才出报告 |
| 跟踪参数 | 丢失保留 3 s；最短轨迹 2 s；关联与拼接代价阈值 | 按 §2.4 实测调整 |
| `sync_metric` | 相对标准 / 相对集体中位 | 每人每式的时间偏移（s）与速度比 |
| 逐人选项 | 镜像、身高（比例尺） | 默认全体一致，可逐人覆盖 |
| 隐私 | 人脸模糊、仅保存姿态 | 多人场景必须先取得同意 |

**新增的集体层指标**
- **同步**：每人每式相对参照的时间偏移与速度比，来自现有对应路径，无需新算法。
- **一致性**：同一时刻各人指标的离散度，例如第三式上举手的高度。
- **问题排行**：每人未达标的重点指标数，以及最严重的一项。

## 4. 计算量估计（GPU 服务器）

- 自上而下方案中，姿态推理按人数线性增长。以 RTMW-l 为例，横评中单人约 7 ms/帧，6 人约 45 ms/帧；10 fps 采样下，10 分钟视频约 4.5 分钟。
- 检测、跟踪各增加约 5–10 ms/帧。
- 这些是按横评单人数据线性外推的估计，需实测。

## 5. 前端设计

**① 总览（新的第一页）**
- 视频上叠加每人的彩色框与编号，颜色固定跟随 ID；下方是人员条，每人一张缩略图。
- **人员 × 动作段矩阵**：行是人，列是各式，格子显示达标比例与最严重问题；点击进入该人的单人工作台。
- **同步时间线**：横轴为标准时间，每人一条线表示超前或滞后；整体落后与个别落后一目了然。

**② 身份轨迹条**
- 每个 ID 一条横条：实线 = 跟踪到，虚线 = 丢失或补齐，⚠ = 疑似交换点。
- 点击 ⚠ 可预览前后 2 秒，并执行合并、拆分或交换。

**③ 单人工作台（复用现有）**
- 从总览点进来即是现有工作台，只多一个“切换人员”下拉框。
- 左侧标准、右侧所选人员；可选“对比两人”，把右侧换成另一名练习者。

**④ 报告与导出**
- 每人一份现有格式的报告（`motioncoach.report/0.5`），外加一个集体汇总，含身份确认记录与同步指标。

## 5b. 前端形态：与单人分析结合，还是单独设计？（调研结论）

**结论：结合为主。新增一个“集体总览”入口页和一个“身份核对”页；逐人细节复用现有单人工作台，不另做一套预览前端。**

依据：
1. **信息查找的经典原则**是“先总览，再缩放与筛选，最后按需查看细节”（Shneiderman 1996，*The Eyes Have It*）。
   - 多人场景缺的是“总览”和“筛选”两层，这正是要新增的集体总览页；
   - “细节”就是单人工作台已经做好的逐项对比。
   - 另做一套细节界面只会重复。
2. **成熟的体育视频分析产品是“团队与个人同一平台”的做法**：
   - Dartfish 等工具在同一套工具中既评估个人也评估全队；
   - Catapult 的视频平台把团队数据与多机位视频连在一起，供教练与分析人员查看。
   公开资料没有给出它们具体的导航设计，这里只引用其“同一平台、团队与个人共存”的定位。
3. **集体练习的反馈研究与专利**中，常见做法是“教练看到全体参与者的面板，再对个人给出针对性反馈”。这是总览到个人的结构，不是两套独立界面。
4. **身份修正是多人特有、单人没有的任务**，需要单独的界面。参照标注工具 CVAT 的轨迹编辑：
   - 物体短暂消失又出现时，把几段轨迹“合并”为一条；
   - 发生身份交换时，在交换点“拆分”后重新连接。
5. **数据层已按此设计**：每位练习者输出一份标准的单人报告（`motioncoach.report/0.5`），集体结果另存 `motioncoach.group/0`。单人工作台无需改动即可打开任一练习者。

**页面结构**

| 页面 | 新增 / 复用 | 内容 |
|---|---|---|
| 集体总览 | 新增 | 视频上叠加编号框；人员缩略图条（练习者 / 排除，附原因）；人员 × 动作段达标矩阵；同步曲线（每人相对群体超前或落后）；一致性热图（各式各指标的离散度）；俯视示意的站位图（按等身高估算） |
| 身份核对 | 新增，仅在需要时出现 | 每个身份一条时间条（实线 = 跟踪到，缺口 = 丢失，⚠ = 疑似交换或拼接点）；合并、拆分、改为练习者 / 排除，确认后重算 |
| 个人详情 | 复用现有工作台 | 从总览点进来；顶部加“切换练习者”和“回到集体” |

## 6. 实施顺序（建议）

1. 姿态层改为输出**多人 + 稳定 ID**：新接口，单人接口保持兼容。
2. 离线拼接与人工确认，先在合成双人视频上验证。
3. 逐人复用单人引擎；报告按人生成。
4. 集体层指标与总览界面。
5. 实拍集体视频验收（§2.4）。

## 7. 实施记录（2026-10-21，后端）

**模块**

| 模块 | 内容 |
|---|---|
| `perception/multi.py` | 每个采样帧的全部人体：关键点、检测框、检测分数（身体关节平均置信度）、外观（躯干与腿部的 HSV 直方图）。与单人路径共用解码与采样网格（`perception/base.sampled_frames`） |
| `engine/tracking.py` | ByteTrack 关联（卡尔曼 + 高低分两轮匈牙利匹配），相似度 = 框 IoU 与关键点相似度 OKS 各半；阈值偏严，只产生可信的短轨迹。自行实现：现有 Python 包或依赖 `opencv-python`（与 MediaPipe 的 opencv-contrib 冲突），或为 AGPL |
| `engine/group.py` | 开头 10 s 建立身份基准（脚点、身高、外观、肢体比例）→ 长轨迹优先拼接到基准，以身高为单位的脚点距离为主，允许前后两段在交接处短暂重叠 → 站位（§9：头部尺度 + 脚点着地，不假设等身高）→ 练习者筛选 → 同步与一致性；身份修改（合并、拆分、指定练习者）按顺序重放 |
| `apps/group.py`、`motioncoach group` | 多人姿态（缓存）→ 身份 → 每位练习者走单人比较（`run_analysis(user_poses=…)`）→ `group.json` + 每人一份报告 |
| `research/group_synth.py` | 合成测试视频与评价 |

**练习者筛选规则**（`GroupParams`，均可调，并可在网页上逐人修改，或命令行 `--include` / `--exclude`）
- 排除：
  - 人物过小（身高低于画高的 10%），无法测量；
  - 出现时间少于 30%；
  - 几乎不动（1 s 平滑后的动作幅度低于群体中位数的 30%）；
  - 位置远在人群之后（深度 > 1.8 倍人群中位深度），并且脚点不在人群的地面上；或者与人群动作不相似且动作幅度低于中位数的 60%。
- 远处但在同一地面上、明显在动的人（后排练习者）保留，并列出原因供核对。
- 判断用深度而不是相对身高：矮个子或儿童站在前排不会被误判为“背景”。

**合成视频验证**（GPU 服务器；150 s，1920×1080）

内容：三位衣着完全相同的示范者，分别同步、晚 1.5 s、1.1 倍速；一位不同的练习者站在后排；两位静止旁观者；40–48 s 一块灰色遮挡条依次扫过所有人。

| 项 | 期望 | 结果 |
|---|---|---|
| 练习者识别 | P1–P4 | P1–P4，全部正确 |
| 衣着相同的三人经过遮挡 | 各 1 个身份、无交换 | 各 1 个，覆盖 98.8–99.6% |
| 旁观者 | 排除 | S2 排除（几乎不动、脚点不在地面线上）；S1 过小，检测器未检出 |
| 同步：P2 − P1 | +1.5 s | +1.50 s |
| 同步：P3 − P1（逐段） | −1.36 / −3.77 / −6.23 / −9.27 / −12.27 s | −1.15 / −3.90 / −6.25 / −9.30 / −12.19 s |
| 逐人比较（P1–P3 与标准相同） | 全部达标 | 29/29、28/28、28/28 |
| 耗时 | — | 多人姿态 34 s（RTMW-l，5 人）；身份 0.4 s；4 人比较 22 s |

**已知不足**
- 后排小人物（约 200 px）检测时断时续，被分成两个身份。主身份覆盖 61%，碎片因出现时间短被排除，没有被拼回。
- 合成视频没有真实的交叉换位、前后排遮挡和镜头运动，需要实拍集体视频验收（§2.4）。
- 一致性指标在只有一位练习者覆盖某段时为空。
- 修复中发现并修正了一个单人流程也存在的问题：练习者视频只覆盖套路前半段时，后面各段在区间评估中报错。现在这些段标注“练习者视频在此段之前已结束”，不参与分析。

## 8. 前端实现（2026-10-21）

按 §5b 的结论：新增两个页面，逐人细节复用单人工作台。

| 页面 | 入口 | 内容 |
|---|---|---|
| 新建分析 | 第 5 步“画面中的人数 → 多人” | 自动改用支持多人的姿态模型（`MOTIONCOACH_GROUP_BACKEND`，默认 RTMW-l） |

## 9. 站位估计：不假设人人等高（2026-10-21）

**问题**：按“等身高”换算深度时，身高差直接变成深度误差。真实人群的身高差可达 10–20%，儿童更多，因此早先的做法不适用。

**哪些人体尺寸在不同人之间差别小**（有来源的数据）：

| 尺寸 | 人群差异 | 男女差 | 在画面中的长度（人高 500 px 时） | 说明 |
|---|---|---|---|---|
| 两眼间距（瞳距） | 均值 63.4 mm，SD 3.8 mm，约 6% | 64.7 vs 62.3 mm，约 4% | 约 19 px | 来源：Dodgson 2004，美军 ANSUR 数据 3976 人 |
| 头宽 | 一项 50 人研究：男 158.2 ± 6.0 mm（3.8%），女 154.0 ± 6.2 mm | 约 3% | 约 47 px | 来源：PLoS ONE 2014 表 2（非 ANSUR） |
| 身高 | 男女平均相差约 7%（169.7 vs 158.0 cm，中国 2020 报告） | 约 7% | 500 px | 儿童：头部占身长从出生时约 1/4 降到成人约 1/7，头的变化远小于身高 |

- 结论：**头部尺寸（眼距、耳距、头宽）个体差异约为身高差异的一半，且受年龄影响小得多**，适合做深度线索。
- 脸部面积是两个长度之积：个体差异约翻倍，还受转头影响。用线性长度更好。
- 代价是**头在画面中很小**：远处 200 px 高的人，眼距只有约 7–8 px，1 px 的关键点误差就是 13%。
- 处理：对每人全片取 1 s 滑动中位后的 80 百分位（正脸时最大，同时抑制抖动）；耳距按人群自身的“耳距 / 眼距”中位比换算成眼距单位，无需头宽的绝对值。

**做法**（`engine/group.py::_layout`）：三种线索按各自的精度加权，在对数域平均。
1. 头部尺度：误差 = 人群差异 6% 与 1.5 px / 测得长度的合成。
2. 脚点着地：地面平坦、相机大致水平时，脚点到地平线的像素距离与深度成反比，与身材无关。地平线与比例系数由各人的头部尺度深度稳健拟合；不在地面线上的人不用这条线索。
3. 身高：只作弱线索（误差按 9%）。

输出每人的横向位置、深度、**估计的真实身高**和各线索的值。焦距按假定视场角 65° 计算，只影响米制数值，不影响前后左右的比例关系。

**验证**（单元测试，针孔相机合成；1.50 m 与 1.85 m 两人并排在 5 m、1.68 m 一人在 7 m，头部尺寸相同）：
- 三人深度误差都在 5% 内，估计身高误差都在 3% 内；
- 只按等身高时，矮者被估远约 9%，高者被估近约 13%。
