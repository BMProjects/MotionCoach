## 1. SportsGPT（arXiv 2512.14121，2025-12）

### 1.1 方法与数据（据论文 v2 正文）

| 环节 | 做法 |
|---|---|
| 姿态 | 由姿态估计模块提取骨架，论文未写明所用模型；角度特征对平面内旋转不变，推测为 2D |
| **MotionDTW**（对齐、抽关键帧） | 特征：髋、膝、踝、肩关节角 Θ，加角速度、角加速度（中心差分），每帧向量 [Θ, 0.39·Θ̇, 0.25·Θ̈]，并拼接前后各 4 帧作时间窗；距离为按关节加权的欧氏距离（如跳跃中膝权重高）。**第一阶段**：用归一化 FastDTW 滑窗做子序列匹配，找出与参考模板最相符的动作区间，去掉前后无关帧。**第二阶段**：区间内带宽约束的 FastDTW 对齐，把参考关键帧映射到用户序列 |
| **KISMAM**（可解释评估） | 每个指标的正常范围 [T_min, T_max] 来自 100 名青少年短跑运动员的统计分布；偏差 D = 超出范围的量（范围内为 0）；用“指标 → 问题”映射矩阵 W 计算每个技术问题的得分 S = Σ D·W，归一化后取前 6 个问题作为诊断 |
| **SportsRAG**（训练建议） | Qwen3-8B，不微调；知识库约 60 亿 token，三层：200 余本教材与期刊、5 万条人工标注问答、1,000 份历史分析报告；检索分三步：偏差标签改写成查询 → 取前 K 段 → 与诊断拼接成增强提示 |
| 数据 | 390 段视频：立定跳远 + 100 m 的四个阶段；标注骨架关键点与关键帧 |

### 1.2 结果（论文报告）

- **对齐误差**：五类平均 1.54 帧，单次推理 1.42 ms。
  - 消融：去掉关节权重 2.61 帧；去掉速度和加速度特征 2.74 帧；只用单一关节 1.79 帧；改成单阶段 66–77 帧。
  - Soft-DTW 在高速段“对齐坍缩”。
- **诊断**：前 6 问题与专家答案的 IoU 只给了箱线图，没有数值。
- **建议质量**：3 位资深专家对 60 份报告双盲打分（1–5 分），SportsGPT 的准确性 3.80、全面性 3.75、专业性 3.73、可行性 3.77。对照组：GPT-5 为 3.15 / 3.43 / 3.07 / 3.53，Claude 4.5 Opus 为 3.00 / 3.65 / 3.13 / 3.63。
  - 消融：去掉评估模块，准确性 3.9 → 2.85；去掉检索，可行性 3.9 → 1.65。
- **自述局限**：
  - 依赖单一参考序列，计划用多参考投票；
  - 只覆盖田径；
  - 真实训练效果未验证，计划做纵向干预研究。
- **文中可见的不一致**：
  - 消融基线（3.9）与主表（3.80 / 3.77）不一致，论文未解释；
  - 正常范围来自“100 名青少年”，参考模型却称来自“100 段精英运动员序列”。

### 1.3 是否开源

**没有。** 论文正文与 arXiv 页面都没有给出代码、数据或模型链接；检索 GitHub 与论文索引页也没有找到实现。作者只在“未来工作”中提到计划发布不同规模的模型库（model zoo）。因此只能作为**设计参照**，无法作为可复现的基线。

### 1.4 与本项目对照

| 方面 | SportsGPT | 本项目（0.5） | 判断 |
|---|---|---|---|
| 粗定位 | 子序列 FastDTW 找动作区间 | 镜像不变特征粗 DTW 找各式区间 | 思路相同；都证明单阶段对齐不可行（其单阶段误差 66–77 帧，与本项目 I2 的诊断一致） |
| 细对齐 | 区间内带宽约束 FastDTW；参考关键帧映射 | **标准重复模板搜索**（多速率、斜率 0.5–2 的子序列 DTW）；逐次重复对应 | 本项目处理“1 次示范 ↔ 6 次练习”、左右交替、镜像录制；SportsGPT 面向单次动作（短跑阶段、跳远） |
| 特征 | 关节角 + 角速度 + 角加速度 + 时间窗；关节权重 | 14 项角度 / 比例特征 + 速度（权重 0.5）；不加权 | **可借鉴**：加速度项、按式加权 |
| 评估 | 群体分布得到正常范围；指标 → 问题映射矩阵；取前 6 问题 | 与单一标准比较、按容差判定、按严重度排序重点 | **可借鉴**：多示范者分布容差、技术问题映射 |
| 不可测处理 | 未涉及 | “不可评价 / 此视角不可测 / 对应不可靠”门控 | 本项目更严谨，保留 |
| 建议生成 | Qwen3-8B + 大型知识库检索 | 规则文字；LLM 层已设计（`LLM_COACH_DESIGN.md`） | 路线一致；其消融说明“评估模块”决定准确性、“检索”决定可行性 |
| 评测 | 帧误差、问题集合 IoU、专家四维盲评 | 重复 F1、定势命中、左右交替等（`ALIGNMENT_STUDY.md`） | **可借鉴**：问题集合 IoU、四维专家盲评与消融设计 |

### 1.5 可借鉴之处与优化方向（按投入从小到大）

1. **在模板搜索中加入加速度项，并按式给重点指标加权**。SportsGPT 消融显示，动态特征和关节权重各贡献约 1 帧误差。实施：用研究框架做一次 A/B（`align_compare` 增加变体），以定势命中和重复 F1 判定是否采用。
2. **技术问题映射**：在 profile 中为每式定义“技术问题”及其与指标偏差的权重，例如“托天不充分 = 肘角偏小 × 0.6 + 腕高偏低 × 0.4”。报告从“指标偏差”升级为“前 N 个技术问题”。让教练标注问题集合后，用 IoU 评价诊断。
3. **多示范者容差**：采集 3–5 位教练的标准示范，按每个指标在定势中的分布确定 [下限, 上限]，替代现在“单一示范 ± 固定容差”。这同时解决两者共同的“单一参考偏差”。
4. **评测设计**：LLM 层上线前采用“专家四维双盲评分 + 去掉证据 / 去掉检索的消融”。
5. **知识库分层**：教材、问答、历史报告三层，本项目可从教练审定的要领条目和本系统的历史报告起步。

不建议照搬：
- **FastDTW**：近似 DTW，在本项目规模下精确 DTW 已足够快，模板搜索每段为毫秒级。
- **大规模知识库**：数据量远超本项目可得。

## 3. 对本项目的经验与改进点

**经验**

1. **“先定位错误、再生成语言”** 是共同结构：CoachMe 有出错片段预测，SportsGPT 有问题诊断，然后才交给语言模型。本项目的逐次重复、逐定势偏差已经完成“定位”，LLM 层只需负责表达。这与上述工作的消融结论一致：评估模块决定准确性。
2. **动作 token 化（VQ-VAE）+ 语言模型**（MotionGPT、LLM-AR）能让模型直接“读”动作，但依赖大规模动作-文本配对数据（HumanML3D 约 2.3 万条）。八段锦没有这样的数据，现阶段结构化证据路线更省数据、可核查。
3. **小领域数据可以微调，前提是先在通用动作-文本数据上预训练**。CoachMe 每项运动只有约 200 段视频。这给出了数据规模目标：约 200 段带教练评语的八段锦练习。
4. **3D 提升可补正面 2D 的盲区**（MotionBERT 的 2D → 3D 预训练、CoachMe 用的 HybrIK）。前屈角度、转体、提踵在正面 2D 中不可测，可由 2D 关键点离线提升到 3D 后测量；代价是推理时间（CoachMe 中 HybrIK 占约 90%）。
5. **分阶段评估**（AQA 的子动作切分）：本项目的模板搜索路径已能把练习者每次重复映射到“起势 / 到位 / 定势 / 还原”，具备分阶段评分的条件。
6. **纠正语句的组织方式**（PoseFix）：由“两姿态之差”生成“身体部位 + 方向 + 幅度”的句子，适合作为规则文字与 LLM 输出的共同格式，并可积累成中文语料。

**改进点（建议排期）**

| 优先级 | 改进 | 依据 | 落点 |
|---|---|---|---|
| P1（无需训练） | 分阶段指标：每次重复的到位时长、定势保持时长、还原速度 | AQA 分阶段；SportsGPT 关键帧 | `engine/templates.py` 已有路径，按阶段汇总 |
| P1 | 技术问题映射与前 N 问题诊断 | SportsGPT KISMAM | profile 增加 `faults`，规则层输出 |
| P1 | 模板搜索加入加速度、按式加权的 A/B | SportsGPT MotionDTW 消融 | 研究框架 `align_compare` 新变体 |
| P2 | 多示范者分布容差 | SportsGPT 群体范围、单参考偏差 | 参考资产支持多段示范 |
| P2 | 2D → 3D 提升实验（MotionBERT 类），评估前屈、转体可测性 | MotionBERT、CoachMe | B 角色横评新增一栏 |
| P3 | 采集“证据 → 教练评语”数据（参照 Ego-Exo4D 的边看边说），达到约 200 段后评估 CoachMe 式小模型微调 | CoachMe 数据规模 | LLM 设计 L3 阶段 |
